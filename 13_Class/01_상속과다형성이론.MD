# 클래스 Part.2 — 상속과 다형성

## 상속이란?

**상속(inheritance)** 은 기존 클래스(부모·기반 클래스)의 공통 데이터와 기능을 새 클래스(자식·파생 클래스)가 물려받는 기능입니다.

```cpp
class Character
{
    // 공통 데이터와 기능
};

class Warrior : public Character
{
    // 전사만의 데이터와 기능
};
```

게임의 전사, 마법사, 궁수는 모두 이름·체력·공격 기능을 가질 수 있습니다. 이 공통 부분을 `Character`에 두고 각 직업은 필요한 부분만 추가하면 중복 코드가 줄어듭니다.

`class Warrior : public Character`의 `public`은 **상속 방식**입니다. 입문 단계에서는 일반적으로 `public` 상속을 사용합니다. “전사는 캐릭터이다”처럼 파생 객체를 기반 객체로도 다룰 수 있게 합니다.

## 상속과 접근 지정자

파생 클래스는 기반 클래스의 `public`, `protected` 멤버에는 접근할 수 있지만 `private` 멤버에는 직접 접근할 수 없습니다.

| 기반 클래스의 멤버 | 파생 클래스 내부 | 외부 코드 |
| --- | --- | --- |
| `public` | 접근 가능 | 접근 가능 |
| `protected` | 접근 가능 | 접근 불가 |
| `private` | 직접 접근 불가 | 접근 불가 |

`private` 데이터가 자식에게도 필요하다면 무조건 `protected`로 바꾸기보다, 먼저 기반 클래스의 `public` 또는 `protected` 멤버 함수를 제공할 수 있는지 생각합니다. 데이터의 변경 규칙을 지키기 쉬워집니다.

## 생성자와 소멸자 순서

파생 객체를 만들면 기반 부분부터 먼저 준비해야 합니다.

1. 생성: **부모 → 자식**
2. 소멸: **자식 → 부모**

자식 객체가 부모 객체를 포함하고 있기 때문에, 부모를 먼저 만들고 자식을 얹습니다. 제거할 때는 반대로 자식 부분부터 정리합니다.

## 가상 함수와 다형성

기반 클래스 함수에 `virtual`을 붙이고, 파생 클래스에서 같은 형태의 함수를 자신의 동작으로 **오버라이딩(Overriding, 재정의)** 하면 부모 포인터로 호출해도 **실제 객체의 함수**가 실행됩니다. 이것이 실행 시간 다형성입니다.

```cpp
Character* character = &warrior;
character->Attack(); // Warrior::Attack() 호출
```

- `virtual`: 기반 클래스가 “이 함수는 자식이 오버라이딩할 수 있다”고 선언합니다.
- `override`: 파생 클래스가 “기반 클래스의 가상 함수를 정확히 오버라이딩한다”고 컴파일러에 확인받습니다. 오타나 매개변수 불일치를 찾아 주므로 붙이는 습관을 권장합니다.

오버라이딩은 부모에게 이미 있는 함수를 자식이 **같은 이름·반환형·매개변수 형태**로 다시 구현하는 것입니다. 이전 함수 단원에서 배운 오버로딩(매개변수 형태가 다른 같은 이름의 함수를 여러 개 만드는 것)과 구별해야 합니다.

## 가상 소멸자

기반 클래스 포인터로 파생 객체를 `delete`할 가능성이 있다면, 기반 클래스의 소멸자는 반드시 `virtual`로 선언합니다.

```cpp
class Character
{
public:
    virtual ~Character() = default;
};
```

그러면 `Character*`가 실제로 `Warrior`를 가리킬 때 `delete`해도 `Warrior` 소멸자부터 올바른 순서로 호출됩니다. 이 프로젝트의 예제는 지역 객체와 주소만 사용해 직접 `new`/`delete`하지 않지만, 이 규칙은 꼭 기억합니다.

## 가상 함수 테이블(vtable)과 vfptr

가상 함수를 부모 포인터로 호출했을 때 실제 객체에 맞는 함수를 어떻게 찾을까요? MSVC를 포함한 많은 C++ 컴파일러는 보통 **가상 함수 테이블(virtual function table, vtable 또는 vftable)** 을 이용해 이를 구현합니다.

```text
Character의 가상 함수 테이블: [ Character::Attack 주소 ]
Warrior의 가상 함수 테이블  : [ Warrior::Attack 주소 ]

Character* character = &warrior;
character->Attack();
        ↓
warrior 객체 안의 vfptr이 Warrior용 가상 함수 테이블을 가리킴
        ↓
Warrior::Attack 주소를 찾아 호출
```

- **vtable**: 클래스의 가상 함수 주소들을 담아 두는 컴파일러 구현용 표입니다.
- **vfptr**(virtual function table pointer): 가상 함수를 가진 각 객체 안에 컴파일러가 두는, 해당 vtable을 가리키는 숨겨진 포인터입니다.

### `virtual` 하나만 붙여도 vtable이 생기나요?

`virtual` 함수가 하나라도 있으면 그 클래스는 **다형적 클래스(polymorphic class)** 가 됩니다. 많은 컴파일러(MSVC 포함)는 이때 동적 호출을 구현하기 위해 vtable과 객체 내부의 vfptr을 만듭니다. `virtual` 소멸자도 가상 함수이므로 똑같이 해당합니다.

다만 **C++ 표준은 vtable이나 vfptr이라는 정확한 자료구조를 요구하지 않습니다.** 표준이 보장하는 것은 가상 함수 호출의 동작이며, 어떤 내부 구조를 쓸지는 컴파일러의 선택입니다. 따라서 `sizeof` 결과, vfptr의 위치, vtable의 메모리 영역은 컴파일러·플랫폼·빌드 옵션에 따라 달라질 수 있습니다.

MSVC x64에서는 가상 함수를 하나 이상 가진 빈 클래스의 크기가 보통 포인터 크기인 8바이트로 관찰됩니다. 이는 vfptr을 저장하기 위한 일반적인 결과일 뿐, 모든 C++ 환경에서 항상 같은 크기라는 보장은 아닙니다.

## 생성자에는 왜 `virtual`을 붙이지 않을까?

생성자는 **객체를 만드는 과정 자체를 결정하는 함수**입니다. `Character`를 만들지 `Warrior`를 만들지 먼저 정해야 생성할 객체의 실제 타입과 메모리 구성이 정해집니다. 그래서 C++에는 가상 생성자가 없습니다.

또한 생성자 실행 중에는 파생 클래스 부분이 아직 만들어지지 않았습니다. 이 시점에 파생 클래스의 가상 함수를 호출하면 아직 초기화되지 않은 멤버를 사용하게 될 위험이 있습니다.

```text
Warrior 생성 시작
1. Character 생성자 실행     ← Warrior 부분은 아직 준비 전
2. Warrior 멤버 초기화
3. Warrior 생성자 본문 실행
```

생성자 또는 소멸자 안에서 가상 함수를 호출하면, C++은 더 파생된 클래스의 오버라이딩 함수를 호출하지 않고 **현재 생성·소멸 중인 클래스의 함수**를 호출합니다. 생성자에서 다형성을 기대하면 안 되는 이유입니다.

## 소멸자에는 왜 `virtual`을 붙일까?

소멸자는 생성자와 달리, 부모 포인터로 자식 객체를 제거할 때 **실제 객체 전체를 올바른 순서로 정리해야 하기 때문**입니다.

```cpp
Character* character = new Warrior();
delete character;
```

- `Character` 소멸자가 **virtual**이면: `Warrior` 소멸자 → `Character` 소멸자 순서로 호출됩니다.
- `Character` 소멸자가 **virtual이 아니면**: `Character*`로 `Warrior`를 삭제하는 것은 정의되지 않은 동작입니다. `Warrior`가 가진 자원이 정상 정리되지 않을 수 있습니다.

따라서 기반 클래스 포인터로 파생 객체를 다룰 수 있고 그 포인터로 삭제할 가능성이 있다면 기반 클래스 소멸자를 `virtual`로 선언합니다.

```cpp
virtual ~Character() = default;
```

모든 클래스의 소멸자에 무조건 `virtual`을 붙일 필요는 없습니다. 상속과 다형적 삭제를 의도하지 않는 단순 값 클래스에는 필요하지 않습니다. 입문 단계에서는 **“가상 함수를 가진 기반 클래스라면 가상 소멸자를 우선 고려한다”** 고 기억하면 좋습니다.

## 추상 클래스와 순수 가상 함수

순수 가상 함수는 함수 선언 끝에 `= 0`을 붙입니다.

```cpp
virtual void Attack() const = 0;
```

순수 가상 함수가 하나 이상 있는 클래스는 **추상 클래스**입니다. 추상 클래스는 직접 객체를 만들 수 없고, 자식 클래스가 반드시 그 함수를 오버라이딩하여 구현해야 할 기능의 규칙을 제시합니다.

## 다중 상속과 다이아몬드 문제

클래스는 둘 이상의 기반 클래스를 상속할 수 있습니다. 다만 같은 조상을 여러 경로로 물려받으면 조상 부분이 중복되어 어떤 멤버를 뜻하는지 모호해질 수 있습니다. 이를 **다이아몬드 문제**라고 합니다.

`virtual` 상속은 공통 조상 부분을 하나만 두어 이 문제를 해결하는 방법입니다. 하지만 설계가 복잡해지므로, 실무에서는 역할이 분명한 인터페이스 외에는 다중 상속을 신중하게 사용합니다.
