# 생성자, 복사 생성자, 이동 생성자

## 생성자란?

생성자(Constructor)는 객체가 만들어질 때 자동으로 호출되어, 멤버 변수를 처음 사용할 수 있는 상태로 준비하는 특별한 멤버 함수입니다.

```cpp
class Player
{
public:
    Player() // 클래스 이름과 같고 반환형이 없습니다.
    {
    }
};

Player player; // 이 시점에 Player 생성자가 자동 호출됩니다.
```

- 클래스 이름과 같은 이름을 사용합니다.
- 반환형을 적지 않습니다. `void Player()`도 생성자가 아닙니다.
- 객체를 만들 때 자동 호출되므로 일반 멤버 함수처럼 직접 호출하지 않습니다.
- 매개변수 형태를 달리해 여러 생성자를 만들 수 있습니다. 이를 생성자 오버로딩이라고 합니다.
- 멤버 변수는 생성자 본문의 대입보다 **멤버 초기화 목록**으로 초기화하는 습관이 좋습니다.

```cpp
Player(const std::string& name, int hp)
    : mName(name), mHp(hp)
{
}
```

## 기본 생성자와 매개변수 생성자

- **기본 생성자**: 매개변수가 없는 생성자입니다. `Player player;`에서 호출됩니다.
- **매개변수 생성자**: 처음 만들 때 필요한 값을 받아 초기화합니다. `Player player("기사", 100);`처럼 사용합니다.

생성자를 하나라도 직접 선언하면 컴파일러가 기본 생성자를 자동으로 만들어 주지 않을 수 있습니다. 따라서 기본 형태도 필요하다면 직접 선언해야 합니다.

## 복사 생성자

복사 생성자는 같은 클래스의 다른 객체를 바탕으로 새 객체를 만들 때 호출됩니다.

```cpp
Player copy = original;
// 또는 Player copy(original);
```

형태는 보통 아래와 같습니다.

```cpp
Player(const Player& other);
```

`const Player&`를 쓰는 이유는 원본을 바꾸지 않고, 객체 전체를 다시 복사하지 않기 위해서입니다. 컴파일러가 만들어 주는 기본 복사 생성자는 멤버를 각각 복사합니다. 숫자·`std::string`처럼 스스로 값을 관리하는 멤버는 보통 안전하게 복사됩니다.

## 얕은 복사와 깊은 복사

클래스가 `int*`, 동적 배열처럼 **직접 소유하는 포인터 멤버**를 가질 때는 기본 복사가 위험할 수 있습니다.

### 얕은 복사(Shallow Copy)

포인터가 가리키는 실제 데이터는 새로 만들지 않고, **포인터 주소값만 복사**하는 방식입니다.

```text
원본.mData ─┐
            ├─ 같은 힙 메모리 한 곳
복사본.mData ┘
```

원본과 복사본 중 하나가 값을 바꾸면 다른 하나도 바뀐 것처럼 보이며, 둘 다 `delete`하면 같은 주소를 두 번 해제하는 이중 해제가 발생할 수 있습니다.

### 깊은 복사(Deep Copy)

복사할 때 힙 메모리를 새로 확보하고 실제 값까지 복사하는 방식입니다.

```text
원본.mData   ── 원본용 힙 메모리
복사본.mData ── 복사본용 새 힙 메모리
```

이제 원본과 복사본이 독립적이므로 각각 수정·해제할 수 있습니다.

## 이동 생성자

### lvalue와 rvalue

이동 생성자를 이해하려면 먼저 **값의 종류(value category)** 를 알아야 합니다.

- **lvalue**: 이름을 가지고, 식이 끝난 뒤에도 계속 사용할 수 있는 대상을 가리키는 표현식입니다. 보통 주소를 구할 수 있습니다.
- **rvalue**: 계산 과정에서 잠시 만들어지는 값이나 임시 객체입니다. 보통 독립적인 이름으로 계속 가리키지 않습니다.

```cpp
int score = 10;  // score는 lvalue: 이름이 있는 변수
int total = score + 5;
// score + 5는 rvalue: 계산으로 잠시 만들어진 값
// 10도 rvalue: 리터럴 값
```

이름만 보고 판단하는 간단한 예시는 아래와 같습니다.

```cpp
int value = 100;

int& leftReference = value;       // lvalue 참조: 이름 있는 변수에 연결
const int& readOnlyReference = 10; // const lvalue 참조: 임시 rvalue도 읽기 전용으로 연결 가능
int&& rightReference = 10;        // rvalue 참조: 임시 rvalue에 연결
```

“lvalue는 대입문 왼쪽, rvalue는 오른쪽”은 입문용 기억법일 뿐 정확한 정의는 아닙니다. 예를 들어 `value = 10;`에서 `value`는 왼쪽에 있어 lvalue이고, `score + 5`는 오른쪽에 있어 rvalue이지만, 위치가 아니라 **계속 가리킬 수 있는 대상인지**를 기준으로 이해하는 편이 좋습니다.

### rvalue 참조와 `std::move`

`Type&&`는 rvalue 참조입니다. 주로 임시 객체의 자원을 옮길 수 있게 연결하는 데 사용합니다.

```cpp
DynamicArray original(3);       // original은 이름이 있으므로 lvalue
DynamicArray moved = std::move(original);
```

`std::move(original)`은 `original`을 이동 가능한 값으로 **형변환(cast)** 하여 이동 생성자가 선택될 수 있게 합니다. 실제 자원을 옮기는 작업은 `DynamicArray(DynamicArray&&)` 이동 생성자 안에서 일어납니다.

중요하게, rvalue 참조 변수도 이름을 가지면 그 변수 자체는 lvalue입니다.

```cpp
int&& temporaryReference = 10;
// temporaryReference는 이름이 있으므로 이 표현식 자체는 lvalue입니다.
```

그래서 이동 생성자 안의 `other`도 이름이 있는 lvalue입니다. 다른 곳으로 다시 넘겨 이동시키려면 보통 `std::move(other)`가 다시 필요합니다.

이동 생성자는 임시 객체나 더 이상 자원이 필요 없는 객체의 자원을 새 객체로 **이전**할 때 사용합니다.

```cpp
Player(Player&& other) noexcept;
```

복사는 새 메모리를 만들고 내용을 복사할 수 있지만, 이동은 기존 메모리의 소유권을 넘겨받아 큰 배열·문자열 같은 자원을 더 효율적으로 처리할 수 있습니다.

```cpp
DynamicArray moved = std::move(original);
```

`std::move` 자체가 데이터를 옮기는 함수는 아닙니다. 단지 “이 객체의 자원을 옮겨도 된다”는 형태로 바꾸어 이동 생성자나 이동 대입 연산자가 선택될 수 있게 합니다. 이동 뒤의 원본 객체는 **유효하지만, 이 예제에서는 비어 있는 상태**가 됩니다.

## Rule of 3 / Rule of 5

클래스가 `new`로 직접 소유한 자원을 가진다면 다음 함수를 함께 고민해야 합니다.

- 소멸자
- 복사 생성자
- 복사 대입 연산자
- 이동 생성자 (C++11 이후)
- 이동 대입 연산자 (C++11 이후)

이를 Rule of 3 / Rule of 5라고 부릅니다. 이 단원에서는 생성자와 소멸자를 중심으로 원리를 익히며, 대입 연산자는 이후 연산자 오버로딩에서 자세히 다룹니다. 실제 현대 C++에서는 `std::vector`, `std::string`, `std::unique_ptr`처럼 자원 관리를 맡아 주는 타입을 우선 사용합니다.
