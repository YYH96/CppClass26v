# x64와 x86

`x64`와 `x86`은 프로그램을 어떤 비트 수의 CPU 환경에 맞춰 만들지 나타내는 **플랫폼(아키텍처) 이름**입니다. Visual Studio의 솔루션 플랫폼 선택에서도 볼 수 있습니다.

## x86

`x86`은 32비트 환경을 뜻합니다. 과거 인텔의 32비트 CPU 계열 이름에서 유래했습니다.

- 주소를 표현하는 크기: 32비트
- 포인터 크기: 일반적으로 4바이트

## x64

`x64`는 64비트 환경을 뜻합니다. 오늘날 대부분의 PC가 사용하는 환경입니다.

- 주소를 표현하는 크기: 64비트
- 포인터 크기: 일반적으로 8바이트

## 자료형의 크기와 포인터의 크기

자료형 자체의 크기와 그 자료형을 가리키는 포인터의 크기는 같은 개념이 아닙니다.

```cpp
int number = 10;
int* pNumber = &number;
```

Visual Studio의 일반적인 x64 설정에서는 `int`가 4바이트이고, `int*`는 8바이트입니다. `int*`가 저장하는 것은 정수값이 아니라 주소값이기 때문입니다.

> !기억 - 같은 코드라도 x86과 x64 중 어느 플랫폼으로 빌드했는지에 따라 포인터 크기, 주소 범위, 구조체의 메모리 배치가 달라질 수 있습니다.

수업에서는 보통 `x64`를 사용합니다.

## 버스(Bus)란?

버스는 CPU, 메모리, 저장 장치처럼 컴퓨터의 여러 부품이 **데이터와 신호를 주고받는 통로**입니다. 도로가 여러 장소를 연결하듯, 버스는 컴퓨터 부품을 연결합니다.

예를 들어 CPU가 변수 `number`의 값을 읽으려면, 메모리에게 “이 주소의 데이터를 보내 달라”고 요청해야 합니다. 이때 주소와 요청 신호, 실제 데이터가 이동하는 길이 버스입니다.

### 대표적인 버스 종류

| 종류 | 하는 일 | 비유 |
| --- | --- | --- |
| 데이터 버스 | 실제 데이터 값을 전달 | 물건을 실어 나르는 길 |
| 주소 버스 | 어느 메모리 위치를 사용할지 전달 | 목적지 주소를 적는 길 |
| 제어 버스 | 읽기·쓰기 같은 동작을 전달 | “읽어라”, “저장해라”라는 신호 |

```text
CPU ── 주소 / 제어 버스 ──> 메모리
CPU <──── 데이터 버스 ──── 메모리
```

> !기억 - 버스는 데이터를 저장하는 공간이 아니라, 부품 사이에서 데이터와 신호가 이동하는 통로입니다.

`x64`라는 이름이 곧 “모든 버스가 64비트”라는 뜻은 아닙니다. x64는 주로 CPU가 다루는 레지스터와 주소 체계가 64비트라는 뜻이며, 실제 데이터 버스 폭과 메모리 구성은 하드웨어 설계에 따라 달라질 수 있습니다.

## 메모리 계층 구조

CPU는 매우 빠르지만 RAM에서 데이터를 가져오는 일은 CPU 입장에서는 상대적으로 느립니다. 그래서 자주 사용할 가능성이 높은 데이터를 CPU 가까이에 임시로 보관하는 **캐시 메모리**를 사용합니다.

```text
빠름 / 작음 / 비쌈
CPU 레지스터
캐시 메모리 (L1 → L2 → L3)
RAM(메인 메모리)
SSD / HDD
느림 / 큼 / 저렴
```

변수는 보통 RAM에 존재하지만, CPU가 최근 또는 자주 사용한 데이터는 캐시에 복사되어 있을 수 있습니다. CPU는 먼저 가까운 캐시에서 데이터를 찾고, 없으면 RAM까지 요청을 보냅니다.

## 메모리 적중률(캐시 적중률)

캐시에서 필요한 데이터를 바로 찾은 경우를 **캐시 적중(Cache Hit)** 이라고 합니다. 찾지 못해 더 느린 메모리 단계로 가야 하는 경우는 **캐시 미스(Cache Miss)** 입니다.

```text
캐시 적중률 = 캐시에서 찾은 횟수 / 전체 메모리 접근 횟수 × 100
캐시 미스율 = 100% - 캐시 적중률
```

예를 들어 메모리에 100번 접근했을 때 90번을 캐시에서 찾았다면, 캐시 적중률은 90%이고 미스율은 10%입니다. 적중률이 높을수록 CPU가 RAM을 기다리는 일이 줄어들어 프로그램이 더 빠르게 동작할 가능성이 커집니다.

### 배열과 적중률

배열은 요소가 연속된 메모리 공간에 저장됩니다. 따라서 앞에서부터 순서대로 접근하면, 이미 가져온 데이터 근처의 다음 요소도 캐시에 함께 있을 가능성이 높습니다.

```cpp
int scores[5] = { 70, 80, 90, 100, 95 };

for (int i = 0; i < 5; ++i)
{
    std::cout << scores[i] << '\n'; // 연속된 요소를 순서대로 접근
}
```

처음 배우는 단계에서는 “연속된 배열을 순서대로 읽는 방식이 컴퓨터가 데이터를 가져오는 방식에도 유리하다” 정도로 기억하면 충분합니다.
