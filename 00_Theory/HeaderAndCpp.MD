# 헤더 파일과 cpp 파일

## 파일을 나누는 이유

프로그램의 규모가 커지면 모든 코드를 하나의 `.cpp` 파일에 작성하기 어렵다. 코드가 길어질수록 필요한 기능을 찾기 어렵고, 다른 파일에서 같은 기능을 사용하기도 불편해진다.

그래서 C++에서는 보통 다음처럼 역할을 나눈다.

| 파일 | 역할 |
| --- | --- |
| 헤더 파일 (`.h`, `.hpp`) | 다른 파일에 알려 줄 기능의 **선언**을 작성한다. |
| 소스 파일 (`.cpp`) | 기능이 실제로 어떻게 동작하는지 **정의(구현)**를 작성한다. |

## 선언과 정의

**선언(Declaration)**은 “이런 이름과 형태의 기능이 있다”라고 알려 주는 것이다.

```cpp
// Add.h
int Add(int left, int right);
```

**정의(Definition)**는 그 기능이 실제로 무엇을 하는지 작성하는 것이다.

```cpp
// Add.cpp
int Add(int left, int right)
{
    return left + right;
}
```

함수를 사용하려는 파일은 헤더를 포함한 뒤 함수를 호출할 수 있다.

```cpp
// main.cpp
#include <iostream>
#include "Add.h"

int main()
{
    std::cout << Add(10, 20) << '\n';
    return 0;
}
```

```text
main.cpp  ── #include "Add.h" ──▶ Add 함수의 선언을 확인
Add.cpp   ───────────────────────▶ Add 함수의 실제 구현 제공
```

## `#include`란?

`#include`는 지정한 헤더 파일의 내용을 현재 파일에 포함하라는 전처리기 지시문이다.

```cpp
#include <iostream> // C++ 표준 라이브러리 헤더
#include "Add.h"   // 내가 만든 헤더 파일
```

- `< >`: 컴파일러나 라이브러리가 제공하는 표준 헤더를 포함할 때 주로 사용한다.
- `" "`: 프로젝트 안에서 직접 만든 헤더를 포함할 때 주로 사용한다.

## 헤더 중복 포함 방지

같은 헤더 파일이 여러 경로를 통해 두 번 포함되면 선언이 중복될 수 있다. 헤더 파일에는 보통 한 번만 포함되도록 다음 코드를 작성한다.

```cpp
#pragma once

int Add(int left, int right);
```

`#pragma once`는 이 헤더 파일을 한 번만 포함하도록 한다. Visual Studio 프로젝트에서는 자주 사용하는 방식이다.

## 주의할 점

### 헤더에 함수 정의를 여러 번 작성하지 않는다

일반 함수의 구현을 헤더에 작성하고 여러 `.cpp` 파일이 그 헤더를 포함하면, 링크 단계에서 같은 함수가 여러 번 정의되었다는 오류가 날 수 있다.

```cpp
// Add.h - 일반 함수 구현을 여기에 두면 문제가 될 수 있다.
int Add(int left, int right)
{
    return left + right;
}
```

일반적으로 헤더에는 선언을, `.cpp` 파일에는 정의를 작성한다. 단, `inline` 함수나 템플릿은 규칙이 달라질 수 있으며 나중에 다룬다.

### `main()` 함수는 하나만 빌드한다

실행 파일 하나에는 프로그램 시작점인 `main()` 함수가 하나만 있어야 한다. 수업 프로젝트의 예제 파일마다 `main()`이 있는 이유는 파일을 하나씩 빌드 대상으로 선택해 실행하기 위해서다.

## 정리

```text
헤더 파일(.h)  : 사용할 수 있는 기능의 이름과 형태를 알린다.  → 선언
소스 파일(.cpp): 기능이 실제로 수행할 코드를 작성한다.       → 정의
main.cpp       : 프로그램의 시작점에서 기능을 사용한다.
```

파일을 나누면 역할이 명확해지고, 여러 파일에서 같은 기능을 재사용하기 쉬워진다.
